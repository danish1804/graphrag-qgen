# dataset/ — Question Generation Pipeline

Automated pipeline to generate 200+ exam questions across all domains, difficulties, and combinations. Used to evaluate GraphRAG + Qwen 2.5 7B question generation quality before and after fine-tuning.

---

## Folder Structure

```
dataset/
├── inputs/
│   ├── topics.py               # Domain topic definitions
│   ├── generate_input_csv.py   # Step 1 — generates input CSV
│   └── input_questions.csv     # Generated by Step 1
├── outputs/
│   └── P000233DS_Question_Dataset.xlsx  # Generated by Step 2
├── generate_dataset.py         # Step 2 — calls API, writes Excel
└── README.md                   # This file
```

---

## Step 1 — Generate Input CSV

```bash
python dataset/inputs/generate_input_csv.py
```

Generates `input_questions.csv` with all question combinations:

```
Easy:        5 domains × 15 topics = 75 rows
Medium:      10 domain combos × 3 topics = 30 rows
Hard:        15 multi-domain topics = 15 rows
Case Study:  15 topics = 15 rows
Total:       ~135 rows minimum
```

Review `input_questions.csv` before running Step 2.

---

## Step 2 — Generate Questions

Make sure the server is running first:
```bash
python main_gr.py --mode full
```

Then generate in batches:
```bash
# Generate next 15 questions:
python dataset/generate_dataset.py --batch 15

# Generate specific category only:
python dataset/generate_dataset.py --category easy_deep_learning

# Preview without calling API:
python dataset/generate_dataset.py --dry-run

# Generate all pending at once:
python dataset/generate_dataset.py --batch 999
```

The script saves progress every 5 questions — safe to stop and resume.

---

## Resuming After Stop

The script tracks progress in `input_questions.csv`:
```
status: pending  → not yet generated
status: done     → successfully generated
status: failed   → API error — will retry on next run
```

Running the script again skips `done` rows automatically.

---

## Output Excel Structure

```
Column A-D:   Input parameters (Q_ID, Domain, Difficulty, Type)
Column E-H:   RAG configuration (Objective, Routing, Top K, Seed Ratio)
Column I-K:   Generated output (Question, Answer, Sources)
Column L-O:   LLM Judge scores (Q/A/R scores, Attempts)
Column P-Q:   Human review (Rating, Reviewer name)
Column R:     Remarks
Column S-T:   Meta (Generated at, Status)
```

---

## Human Review Process

After generation team members fill columns P-Q-R:

```
Human Rating: PASS / BORDERLINE / FAIL
Reviewed By:  Your name
Remarks:      Any issues — MCQ format, topic drift, citations
```

Rating guide:
```
PASS:       Question is well-formed, on topic, appropriate difficulty
BORDERLINE: Minor issues — adjacent topic, slightly off difficulty
FAIL:       Wrong topic, MCQ format, citation dependent, not standalone
```
